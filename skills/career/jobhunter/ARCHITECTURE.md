# JobHunter — архитектура

Проект-workflow для Hermes Agent: ищет вакансии, дёшево фильтрует их кодом,
для неоднозначных случаев зовёт LLM Gateway (анализ вакансии + сопоставление
CV), готовит персонализированный отклик и присылает в Telegram — либо
(опционально, где это технически возможно) подаёт заявку автоматически.

Эта версия архитектуры — по вашей схеме: JobHunter как самостоятельный
workflow, Hermes как координатор/интерфейс, LLM Gateway как единая точка
доступа к любой модели (JobHunter не привязан к конкретной LLM). Тот же
шаблон предполагается переиспользовать для других ваших проектов
(X Publisher, CRM, eBay) — см. `PROTOCOL.md`.

## Название проекта

**JobHunter**. Внутренний id скилла — `jobhunter` (поле `name` в `SKILL.md`).

## Что делает JobHunter без LLM (максимум обычного кода)

- получает вакансии (`search_jobs.py`);
- проверяет актуальность / обязательные поля;
- удаляет дубликаты (`state.py`);
- сохраняет вакансии, считает базовые показатели (`state.py`);
- считает rule-based score по `criteria.json`, отсеивает явный мусор
  (красные флаги, чёрный список, исключённые роли/стек) — `match_score.py`;
- отслеживает статус заявки, ведёт историю (`state.py`);
- отправляет сообщения в Telegram (`telegram_notify.py`);
- собирает `JOB_SEARCH_COMPLETED` (`run.py`).

## Где нужен LLM (только там, где нужно понимание)

Ровно три задачи, обе — через `llm_gateway.py`, обе вызываются ТОЛЬКО для
вакансий, уже прошедших дешёвый код-фильтр:

1. **Анализ вакансии** (`vacancy_fit`) — подходит ли вакансия пользователю
   (тоньше, чем ключевые слова: понимает контекст, неявные противопоказания).
2. **CV matching** (`cv_match`) — какие навыки совпадают, каких не хватает.
3. **Персонализация заявки** (`personalize_application`) — адаптирует
   сопроводительное письмо под конкретную вакансию.

JobHunter не знает, будет ли это GPT, Claude или другая модель — он просто
отправляет `LLM_REQUEST` с `task` и `input` (см. `PROTOCOL.md`) и получает
структурированный результат. Если Gateway не подключен — все три задачи имеют
рабочий fallback без ИИ (см. `match_score.py` и `apply_or_notify.py`), workflow
не падает и не блокируется.

## Компоненты → файлы

| Компонент на схеме | Файл | Что делает |
|---|---|---|
| Job Sources | `scripts/search_jobs.py` | 81 источник (16 полных адаптеров: 7 free API + 3 RSS + 6 key-based API, остальные — заглушки под scrape) |
| Filters + Database | `scripts/state.py` | Дедупликация по id, хранение вакансий/статусов/истории (SQLite, без ИИ) |
| Реестр источников | `references/job_sources.json` | База сайтов по категориям — какие имеют API, какие только парсинг/RSS |
| Score / Filter | `scripts/match_score.py` | Детерминированный rule-based score по `criteria.json`, без ИИ |
| Критерии отбора | `references/criteria.json` | Структурированные правила (роли, стек, зарплата, локация, красные флаги) |
| LLM Gateway | `scripts/llm_gateway.py` | Единая точка входа для всех LLM-задач, model-agnostic |
| Application Workflow | `scripts/apply_or_notify.py` | Персонализация письма (LLM Gateway или шаблон) + опц. автоподача hh.ru |
| Резюме | `assets/resume_template.md` | Резюме-основа для сопоставления и писем |
| Telegram-доставка | `scripts/telegram_notify.py` | Уведомления о вакансиях + `JOB_SEARCH_COMPLETED` |
| JobHunter Workflow (координатор всего) | `scripts/run.py` | Точка входа, вызываемая Hermes'ом |
| Контракт LLM_REQUEST / JOB_SEARCH_COMPLETED | `PROTOCOL.md` | Формат сообщений, переиспользуемый для других проектов |

## Почему не «полный автопилот» подачи заявок

У hh.ru есть открытое API для **поиска** вакансий без авторизации, но подача
отклика (`POST /negotiations`) требует OAuth-токен именно вашего аккаунта
соискателя (регистрация приложения на dev.hh.ru + разрешение от вас). У
большинства других площадок (LinkedIn, большинство агрегаторов) публичного
API для отклика вообще нет — только интерфейс сайта, а автоматизация там
обычно нарушает условия использования площадки.

Поэтому базовый режим: workflow находит → оценивает (код + LLM) →
персонализирует → присылает в Telegram, вы одним нажатием
подтверждаете/отправляете сами. Автоподача через hh.ru OAuth — отдельная
настройка (`HH_ACCESS_TOKEN` + `HH_RESUME_ID` в env), место под неё уже есть
в `apply_or_notify.py`.

## Переиспользование для других проектов

Из всей архитектуры model-agnostic и переносимы без изменений:
`llm_gateway.py` (обвязка `request`/`set_backend`) и сам протокол
`LLM_REQUEST` / `JOB_SEARCH_COMPLETED`-подобных событий (`PROTOCOL.md`).
Для X Publisher / CRM / eBay нужно будет заново написать только:
Job Sources → аналог под нужный источник данных, Score/Filter → свои
правила, набор LLM-задач (task) под свою предметную область, Application
Workflow → своё "финальное действие" вместо отправки отклика.

## Что ещё нужно от вас (см. отдельные незакрытые задачи)

1. Заполнить `references/criteria.json` — какие вакансии годятся (роль,
   зарплата, город/удалёнка, стек, красные флаги).
2. Заполнить `assets/resume_template.md` — соберём резюме вместе.
3. Подтвердить список источников в `job_sources.json` (сейчас — хороший
   дефолт для СНГ/IT, можно менять).
4. На стороне Hermes: подключить `llm_gateway.set_backend(...)` к реальной
   модели (см. `SKILL.md`, шаг 0) — без этого шага LLM Task пропускается,
   работает только код-фильтр.
