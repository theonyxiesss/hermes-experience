# Пример одного прогона (концептуально)

1. Hermes Agent по расписанию (`search.interval_hours=3`) активирует скилл `jobhermes`.
2. Читает `criteria_prompt.md`: например, "Backend Python, удалёнка, от 250к, не 1С".
3. Вызывает `search_all("python backend", area=None, hours=3)` →
   получает 12 новых вакансий с hh.ru, RemoteOK, Remotive.
4. 12 - 9 уже есть в `state.db` (видели раньше) = 3 реально новых.
5. Для каждой из 3 вызывает `score_vacancy(vacancy, call_llm=<модель Hermes>)`.
   - Вакансия A: score 85 — "Python/FastAPI, удалёнка, зарплата 280к — почти идеально"
   - Вакансия B: score 40 — "PHP legacy проект, не подходит по стеку"
   - Вакансия C: score 20 — "Требуется 1С — красный флаг из критериев"
6. Порог 70 → проходит только A.
7. `process_vacancy(A, call_llm=..., hh_resume_id=None)` →
   генерирует сопроводительное письмо, `HH_ACCESS_TOKEN` не задан → автоподача
   выключена, только черновик.
8. `notify_vacancy(...)` → пользователю в Telegram приходит сообщение:
   заголовок, компания, зарплата, ссылка, score+причина, текст письма,
   "✉️ Черновик готов — отправьте сами".
9. Все 3 вакансии (A, B, C) записываются в `state.db`, чтобы не повторялись.
10. Если бы за проход не нашлось вакансий выше порога — Telegram не тревожится,
    только раз в сутки короткая сводка "проверено X, подходящих 0".
